# engine: turso_core 0.8.3 (features fs, json, uuid, encryption, conn_raw_api)
# RustFS: the buckwal-rustfs container of scripts/rustfs.sh (plain HTTP, no encryption)
# build: cargo build --release --locked -p buckwal-cli (rustc 1.97.1), target/release/buckwal
# machine: Apple M4 Max, macOS 27.0.1
# laptop (Apple M4 Max, RustFS in podman on the same Mac), not production
# telemetry: BUCKWAL_OTEL unset (off), so no span or log record was exported during these runs.
# One run per configuration; no repeats, so treat small differences as noise.
#
# Workload (bench): as results/batching-knob.txt. CREATE TABLE bench(id INTEGER PRIMARY KEY,
# payload BLOB) on one connection, which is then closed; then 2000 autocommit INSERT OR REPLACE
# statements of a 1024-byte blob shared by --connections threads (one connection each); each
# thread closes its connection when the ids run out; then the database is closed. Default
# settings otherwise. --batching is set with Database::set_batching after open.
#
# Keys: as results/batching-knob.txt, plus
# - commits_behind, oldest_behind_ms: Database::upload_stats() right after the commit threads
#   finished (before the close): the background commits that had returned and were not yet in
#   the bucket, and how long ago the oldest returned. 0 means the uploader had caught up.
# - ack_wait_*: "none" for a background run. A background commit does not wait for its ack, and
#   the histogram holds only the library's own Off commits (a close-time checkpoint's).
# - commit_p50/p95/p99_ms: what the caller waited for each INSERT. For a background commit that
#   is the time to the local fsync. It is not the time until the commit is in the bucket.
#
# Commands (BUCKWAL_* from scripts/rustfs.sh env; BUCKWAL_OTEL and BUCKWAL_BATCHING unset;
# run id 1792857092; <tmp> from mktemp -d, removed afterwards):
#   for C in 1 8; for B in off 'background 5ms 64 1MiB 1000':
#     BUCKWAL_PREFIX=bench/background/c<C>-<off|background>-1792857092 \
#       buckwal bench --dir <tmp>/<tag> --commits 2000 --connections C --batching B
