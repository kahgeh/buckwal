# buckwal

Rust library `buckwal` (crates/buckwal) plus CLI `buckwal` (crates/buckwal-cli) that makes a tursodb database durable in an S3 bucket. Every new bucket is format 5 (ADR 0010, README, Packs): a WAL restart is a generation switch (seal-start record and head, no pages), and a packer uploads whole-file packs (`pack/<G>/<run id>`, `.codes`, `pack-latest`). The packer is a writer thread by default (`BUCKWAL_PACK`, `serve --pack on|off`), or `buckwal pack` (one run) and `buckwal packer` (the loop) on any machine with the key file. `buckwal upgrade DIR` converts a bucket of formats 1 to 4, which seal until then; `buckwal vacuum DIR` runs the in-place `VACUUM`. A database created new in MVCC mode (`--journal-mode mvcc`, `BUCKWAL_JOURNAL_MODE=mvcc`; bucket format v2 before packs) is supported with limits (README, MVCC mode). Switching an existing WAL database, Window batching in MVCC and switching back are refused. A second machine can follow the bucket as a read-only replica (`buckwal follow`, `buckwal::open_replica`; replica IO mode, a follower thread woken by bucket event notifications with a slow poll as the safety net; README, Replicas). `buckwal notify-setup` prints the AWS commands for the notification route and runs nothing. Replicas refuse MVCC databases. Architecture: `docs/architecture.md`, decisions: `docs/adr/`. `buckwal serve` (crates/buckwal-server) serves it over tursodb's SQL over HTTP v3 (`serverless/PROTOCOL.md`, turso 0b2bec917); its clients are tursodb's serverless drivers. tursodb's conformance suite and the Go driver passed against it at eb101d9 and again at 10e62fb; the TypeScript and Python drivers also passed their own tests against it, over plain HTTP and over HTTPS with a token (results/serve-clients.txt); every libSQL client was not run (README, Server, Clients run and not run). crates/buckwal-hrana-client is its test-only client (the name is historical).

## RustFS resource rules

- Only create, stop or remove containers and volumes named `buckwal-*` (use `scripts/rustfs.sh`).
- Never touch `obs-*` or `tursopoc-*` containers or volumes.
- Never stop or reset the podman machine unless it was down before you started and only `buckwal-*` containers run.
- The observability stack (`obs-*`): only send it OTLP and run read-only SELECTs as its read-only ClickHouse user. Never print or write its password.

## Dependency audit rule

- Before adding, upgrading or fetching any crate, run the `rust-supply-chain-auditor` subagent and wait for approval.
- Cargo.lock is the audited lock (see README, Dependency audits). Any change to it needs a re-audit.
- turso_core is `default-features = false, features = ["fs", "json", "uuid", "encryption", "conn_raw_api"]` (audit row 3; `conn_raw_api` is in-crate and added no crate). The replica follower depends on that non-public API: re-run the probes of `docs/read-replicas-recon.md` on any turso_core upgrade. Never enable reqwest's `rustls`, `default-tls` or `native-tls` features (aws-lc/openssl); rustls is ring only.
- Never build with `--cfg antithesis`. Re-audit before targeting wasm.
